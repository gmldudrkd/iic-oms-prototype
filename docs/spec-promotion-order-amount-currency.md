# 스펙 변경 사항 — Promotion Order Amount 구간 통화(Currency) 국가 연동

- 영향 화면: **Promotion 등록/수정 화면 (Add/Edit Promotion V2)**
- 영향 영역: `Target = Order Amount` 의 **Order Amount Ranges**, 및 화면 내 모든 금액 표기
- 신규 메뉴/라우트 없음

---

## 1. 변경 개요

Target 조건이 `Order Amount` 일 때 금액 구간(Range)에 표기되던 통화가 **`KRW` 로 고정**되어 있었습니다.
이를 **상단 헤더 `Brand & Corp` 에서 선택한 법인(국가)의 통화**를 따르도록 변경합니다.

| 항목 | 변경 전 | 변경 후 |
| --- | --- | --- |
| Range 입력 필드 단위 표기 | `KRW` 고정 | 선택 법인의 **통화 코드** (`KRW` / `USD` / `CAD` / `AUD` / `JPY`) |
| Range 금액 표기 (Summary·시뮬레이션) | `₩50,000` 고정 | 선택 법인의 **통화 코드 + 소수점 규칙** (`KRW 50,000`, `AUD 150.50`) |
| 소수점 입력 | 불가 (정수 단위) | 통화별 허용 (KRW·JPY 정수 / USD·CAD·AUD 소수점 2자리) |
| 법인 변경 시 | 해당 없음 | 통화 재계산 + **재확인 안내 배너** 노출 |

---

## 2. 법인(Corporation) → 통화 매핑

| 법인 코드 | 통화 코드 | 소수점 자리 |
| --- | --- | --- |
| `KR` | KRW | 0 |
| `US` | USD | 2 |
| `CA` | CAD | 2 |
| `AU` | AUD | 2 |
| `JP` | JPY | 0 |

- 매핑에 없는 법인이거나 `Brand & Corp` 미선택 상태이면 **기본값 `KRW`** 를 사용합니다.
- 신규 법인이 추가되면 이 매핑 테이블에만 항목을 추가하면 됩니다.

---

## 3. 통화 결정 규칙

| 모드 | 기준 | 비고 |
| --- | --- | --- |
| **등록(Add)** | 상단 헤더 `Brand & Corp` 에서 선택한 법인 | 헤더 선택을 바꾸면 즉시 반영 |
| **수정(Edit)** | 프로모션 **저장 시점의 법인** | 헤더 선택과 무관하게 고정 |

- Promotion 화면은 `Brand & Corp` **단일 선택** 경로입니다(다중 선택 경로: Order / Channel List).
  예외적으로 다중 선택 상태로 진입한 경우, **첫 번째 법인**의 통화를 사용합니다.
- 수정 화면에서 통화를 저장 시점 법인으로 고정하는 이유: 이미 저장된 금액 구간의 의미(=통화)가
  조회하는 사람의 헤더 선택에 따라 달라지면 안 되기 때문입니다.

---

## 4. 화면 표기

### 4-1. 안내 문구 (Target = Order Amount 섹션)

기존 안내 문구 뒤에 통화 기준을 명시합니다.

```
Rewards apply per order amount range. Lower bound is inclusive (≥), upper bound is exclusive (<).
Each range gets its own reward setting in step 4.
Amounts are in {통화코드} — the currency follows the corporation selected in Brand & Corp.
```

### 4-2. Range 입력 필드

- 하한/상한 입력 필드의 우측 단위 표기(endAdornment)가 선택 법인의 **통화 코드**로 표시됩니다.
  - 예) `≥ [ 150.50 ] USD  ~  < [ 300.00 ] USD`
- 입력 단위(step)는 통화의 소수점 규칙을 따릅니다. (KRW·JPY = `1`, USD·CAD·AUD = `0.01`)
- 음수 입력 불가(`min = 0`).

### 4-3. 금액 표기 형식

금액은 **통화 기호가 아닌 ISO 4217 코드**를 숫자 앞에 붙여 표기합니다.
앱 공통 가격 포맷 유틸(`shared/utils/stringUtils.convertToPrice`, 주문 상세 등에서 사용)과 동일한 방식이며,
USD·CAD·AUD 가 모두 `$` 계열 기호를 써서 법인 구분이 모호해지는 문제를 피하기 위함입니다.

| 통화 | 표기 예 |
| --- | --- |
| KRW | `≥ KRW 50,000 ~ < KRW 100,000` |
| AUD | `≥ AUD 150.50 ~ < AUD 300.00` |
| KRW (무제한) | `≥ KRW 200,000 ~ Unlimited` |

- 적용 범위: Range 입력 영역, 우측 **Summary** 의 Target 표기, **Apply Simulation** 의 장바구니 합계·구간 매칭 결과,
  제품 검색 목록의 가격 등 **등록/수정 화면 내 모든 금액 표기**에 동일한 통화가 적용됩니다.
  (구간 금액만 통화가 바뀌고 장바구니 합계는 원화로 남으면 시뮬레이션 결과를 해석할 수 없기 때문)

## 5. 법인 변경 시 동작 (등록 모드)

`Brand & Corp` 선택을 바꿔 통화가 달라지면:

1. **입력한 금액 숫자는 그대로 유지**합니다. (자동 환산하지 않음)
2. 새 통화의 소수점 규칙에 맞게 **반올림**합니다.
   - 예) `AUD 150.50` → `KR` 로 변경 시 `KRW 151`
3. 이미 금액이 입력돼 있던 경우 **재확인 안내 배너**를 노출합니다.

```
⚠ Currency changed to {통화코드}. Amounts were kept as typed — please review each range.
```

4. 사용자가 구간 값을 다시 수정하면 배너는 자동으로 사라집니다.

> **환율 자동 환산은 하지 않습니다.** 프로모션 금액 기준은 각 법인의 정책에 따라 정하는 값이므로,
> 시스템이 임의로 환산하면 의도하지 않은 기준 금액이 저장될 수 있습니다.
> 대신 값을 유지하고 사용자에게 재확인을 요구합니다.

---

## 6. 검증 · 저장

- 기존 Range 검증 규칙(하한 필수, 상한 > 하한, 구간 간 공백·중복 불가, 무제한은 마지막 구간만)은 그대로 유지됩니다.
- 저장 시 금액과 함께 **통화 코드**가 기록되어야 하며, 조회/수정 시 저장된 통화로 표기합니다.

---

## 7. 참고 — 프로토타입 한계

- 프로토타입의 제품 목업 가격은 법인과 무관한 **단일 숫자 세트**입니다.
  따라서 법인을 바꾸면 **표기 통화와 소수점 형식만 바뀌고 금액 숫자 자체는 동일**하게 보입니다.
  (예: `KRW 32,000` → `AUD 32,000.00`)
  실제 운영에서는 제품 가격이 법인별 Price Master 에서 내려오므로 금액도 함께 달라집니다.
